## R01 (P2) — §0.1 and AdicSpacesPartIII §R3.6 each name the other as supplier for the comparison of complete continuity with `Huber.IsCompletelyContinuous`

An implementer cannot tell which roadmap proves the comparison or in which order to build: §0.1's target waits for a predicate that is not at the pins, and the roadmap that defines that predicate waits for §0.1. In §0.1 (README lines 206–211) the text asks to "prove that it agrees with AdicSpacesPartIII's `Huber.IsCompletelyContinuous` (§R3.6, target *completely-continuous-map*)", with "*Needs:* … AdicSpacesPartIII §R3.6 for the affinoid predicate"; the Dependencies of Layer 0 (line 391) and the contract "From TauCetiRoadmap.AdicSpacesPartIII" (lines 1300–1303) repeat the edge. On main, AdicSpacesPartIII's target *completely-continuous-map* (its README lines 9775–9808) says that `Huber.IsCompletelyContinuous` "is the affinoid specialization of CompactOperators §0.1's `IsCompletelyContinuous`", uses `isFiniteRank_iff_range_fg` "to identify the approximation conditions", concludes that "the lattice condition is an equivalent characterization of this predicate", and ends "*Needs:* CompactOperators §0.1"; its dependency paragraph (line 11764) lists CompactOperators §0.1. This README's own Downstream consumers (lines 1132–1136) and Scope (lines 1189–1192) already describe AdicSpacesPartIII as the consumer and as the owner of the affinoid predicate, so the three supplier passages contradict them. The README on main had no such edge: its table gave AdicSpacesPartIII the "`Huber` comparison wrapper" and this roadmap the lattice condition.

The smallest change keeps the direction main has. In §0.1 keep the lattice condition and its equivalence with complete continuity as the target here (it uses nothing of AdicSpacesPartIII), and turn the sentence on the affinoid predicate into a statement about the consumer, for example: "AdicSpacesPartIII §R3.6 (*completely-continuous-map*) identifies its affinoid predicate with this condition over a Noetherian `A`, using `isFiniteRank_iff_range_fg`." Then remove AdicSpacesPartIII §R3.6 from the *Needs:* line of that paragraph and from the Dependencies of Layer 0, and remove the subsection "From TauCetiRoadmap.AdicSpacesPartIII" (the Scope paragraph already records what that roadmap owns). The description's list of supplier contracts then loses its last item.

## N01 — The Check on `diag(ϖⁱ)` in §0.1 cites the rank condition where the strong rank condition is used

Line 225: the argument embeds a free module of rank `m + 1` in a module generated by `m` elements, hence injects `R^(m+1)` into `R^m`; that is excluded by the strong rank condition (Mathlib `StrongRankCondition`, on injections), which nonzero commutative rings satisfy, not by the rank condition (on surjections).

## N02 — `resolventCoeff` is declared in `Suggested.lean` but no statement there uses it

Line 265. It could be said in its docstring that it is the name README §2.4 uses, or the definition could stay in the README only.
