# Review of AxKochenErshov (pull request #2868 at 968572e)

**Verdict:** needs changes

**Summary.** Changes are needed: five findings, all repairable by editing sentences. Layer 1 plans quantifier elimination for algebraically closed valued fields, which RigidAnalyticGeometry §8.2 on main already owns; two statements are false as written (the description of the set of pseudolimits in 2.1, and the complete discrete valuation ring of 5.6 without an unramified hypothesis); one API bullet of 2.1 fails for constant polynomials; and the finitely ramified theorem 5.8, a headline, is statable at the pins but absent from `Suggested.lean`. ## R01 (P2) — Layer 1 plans the language with a divisibility relation, the theory ACVF and its quantifier elimination, which RigidAnalyticGeometry §8.2 on main already owns

Two roadmaps would each build the same theory and the same theorem, with nothing saying which declaration the other uses. RigidAnalyticGeometry on main states, as a target of its own (`TauCetiRoadmap/RigidAnalyticGeometry/README.md`, §8.2, lines 1787–1835): the ring language enlarged by one binary symbol `∣` read `x∣y ⟺ v(y) ≤ v(x)`, the axioms of ACVF including `∃x ¬(1∣x)`, "Prove that ACVF eliminates quantifiers", and, as step (iii) of its route, the conjugacy of the prolongations to the algebraic closure. Its `Suggested.lean` docstring names the theorem as a README target. Here Layer 1 states the same theory (`Theory.acvf`), the same conjugacy and the same elimination (README lines 129–145), and Scope and ownership says this roadmap owns "the one-sorted language of valued fields" and "Robinson's theorem on algebraically closed valued fields". The reading of `∣` agrees on both sides (`x ∣ y` iff `|y| ≤ |x|`), so there is no convention clash, only two owners. ClassicalAdicEtaleCohomology §9.2 on main (`aic_valuation_finite_conditions_transfer`) is a third place that uses the same elimination.

A roadmap on main is earlier than an open one. The smallest change: in Layer 1 cite RigidAnalyticGeometry §8.2 for the language's reading, the ACVF axioms, the conjugacy of prolongations and the elimination, and keep as targets here only what §8.2 does not state (the inequality `[k_L : k_K]·[Γ_L : Γ_K] ≤ [L : K]`, the completions of Cor. 3.34, the one-variable definable sets, the bridge to `ValuationSubring`); add RigidAnalyticGeometry §8.2 to the supplier contracts; and change the ownership sentence and the Summary's "is the first theorem of the roadmap" to match.

## R02 (P2) — In 2.1 the set of pseudolimits is described as a ball whose radius is "the eventual value of `|a_{i+1} − a_i|`", but that quantity has no eventual value

An implementer cannot state this bullet (README lines 173–174): for a pseudo-Cauchy sequence, `|a_{i+1} − a_i|` is eventually strictly decreasing by the definition two lines above, and for a pseudolimit `x` it equals `|x − a_i|`. In `ℚ` with partial sums of `∑ pⁿ` the values are `p⁻¹, p⁻², …`. The set of pseudolimits is `{y : |x − y| < |x − a_i| for all large i}`, an intersection of balls that in general is not a ball of any radius in `Γ`. `Suggested.lean` states the correct form (`IsPseudoLimit.isPseudoLimit_iff`, line 119), so README and Lean disagree.

Smallest change: replace the bullet by the Lean statement in prose: if `x` is a pseudolimit, then `y` is one exactly when `|x − y| < |x − a_i|` for all large `i`.

## R03 (P2) — The sentence of 5.6 citing Lem. 7.14 is false for a general field of mixed characteristic: it needs `K` unramified (or finitely ramified)

Section 5.6 opens "For `K` of mixed characteristic `(0, p)`" and then says that when `K` is `ℵ₁`-saturated the valuation ring induced on the residue field of the coarsening "is a complete discrete valuation ring" (README lines 365–369); the unramified hypothesis appears only in the following sentence. Take an `ℵ₁`-saturated elementary extension `K` of `ℂ_p`: its value group is divisible, so the convex subgroup `Δ` generated by `|p|` is divisible and nontrivial, and the induced valuation with value group `Δ` is not discrete.

Smallest change: state the hypothesis where it is used, for instance "when `K` is unramified (or finitely ramified) and `ℵ₁`-saturated, the corresponding valuation ring is a complete discrete valuation ring".

## R04 (P2) — The finitely ramified theorem 5.8 is a headline and is statable at the pins, but `Suggested.lean` omits it and names no missing carrier

The Summary gives the finitely ramified case as the third case of the principle, and Downstream consumers says PadicallyClosedFields rests on it, yet the acceptance test does not contain it; the module docstring only says it is "stated in `README.md` only". Every carrier exists: I elaborated, on a scratch copy of the file, a statement with hypothesis `{γ : V.ValueGroup | V.valuation (p : K) ≤ γ ∧ γ < 1}.Finite` (and the same for `V'`) and conclusion

    K ≅[valLang] K' ↔ (∀ n : ℕ, (V ⧸ IsLocalRing.maximalIdeal V ^ n) ≅[Language.ring]
        (V' ⧸ IsLocalRing.maximalIdeal V' ^ n)) ∧ (valueGroup V ≅[orderedGroup] valueGroup V')

with `sorry` the only warning. Smallest change: add this theorem. The same scratch file elaborates two further Summary statements that are absent, should the author want them: completeness of algebraically closed nontrivially valued fields of fixed characteristics (`IsAlgClosed K`, `V ≠ ⊤`, `CharP K a`, `CharP (ResidueField V) b` give `K ≅[valLang] K'`), and model completeness of the theory of `ℚ_p` (every `valLang`-embedding between fields elementarily equivalent to `ℚ_[p]` is elementary).

## R05 (P2) — The API bullet of 2.1 on polynomials is false for constant `f`

"for a polynomial `f`, `f(a_i)` is pseudo-Cauchy for `i` large" (README line 178): for constant `f` the sequence is constant, `|f(a_k) − f(a_j)| = 0 < 0` fails, and the sequence is not pseudo-Cauchy under the definition of the same section. Smallest change: "for a nonconstant polynomial `f`".

## C01 — The Summary claims more for finitely ramified fields than 5.8 states

"It also holds for finitely ramified fields" follows the sentences giving both the `≡` and the `≼` form, so it reads as both; 5.8 states only the `≡` criterion. Would read correctly as "The equivalence criterion also holds for finitely ramified fields, …".

## C02 — The Check on `ℚ₂` and `𝔽₂((t))` is labelled with the wrong characteristic

The Check (README lines 470–472) concludes "Equicharacteristic `0` and mixed characteristic are not comparable by these theorems", but `𝔽₂((t))` has equicharacteristic `2`. The computation is right (`−1 = 1` is a square in `𝔽₂((t))`, not in `ℚ₂`); the conclusion should say "Equicharacteristic `p` and mixed characteristic", or the example should be replaced by one in equicharacteristic `0`.

## C03 — Two docstrings of `Suggested.lean` describe the unramified hypothesis wrongly, and three carry section numbers the README does not have

The docstrings of `elementarilyEquivalent_iff_of_unramified` and `elementarilyEquivalent_padic_iff` say "`v(p)` is the least value greater than `1`". The hypothesis in the signature, `∀ x, V.valuation x < 1 → V.valuation x ≤ V.valuation p`, says `|p|` is the greatest value below `1`, which is what Conventions says. Also `valueGroup` and the two interpretation theorems are labelled **0.3** (the README has them in 0.2) and the power series theorem **6.3** (README 6.2).

## C04 — `mem_iff_dvd_one` holds by unfolding the definition

`by simp [ValuationSubring.Dvd]` closes it on a scratch copy, so as a target it asks an implementer for nothing. If it is kept as a sanity check that `V = {x | 1 ∣ x}`, mark it as one, or move it to the README as a Check of 0.1.

## C05 — The hypothesis `ha` of `IsPseudoLimit.isPseudoLimit_iff` is implied by `hx`

With `[NoMaxOrder ι]`, a sequence that has a pseudolimit `x` is pseudo-Cauchy: for large `i < j < k`, `|a_j − a_i| = |x − a_i|` and `|a_k − a_j| = |x − a_j| < |x − a_i|`. Neither direction of the equivalence uses `ha`. Dropping it loses nothing; `NoMaxOrder` is needed (on a one-point index every `x`, `y` are pseudolimits and the right side can fail).

## C06 — The README and the description say pseudo-Cauchy sequences are indexed by well-ordered sets; the Lean definitions take any linear order

Conventions and 2.1 say "well-ordered without a largest element", and the description says the file "pins `IsPseudoCauchy` and `IsPseudoLimit` over well-ordered index types". At the head both definitions have `[LinearOrder ι]` only, so on `Fin 2` every sequence is pseudo-Cauchy with every element a pseudolimit. Either say in 2.1 that the predicates are defined for every linear order and the theorems assume no largest element, or add the binders; and correct the sentence of the description.

## C07 — The Teichmüller lift of Tau Ceti is cited under a name that does not exist

`TauCeti.RingTheory.Henselian.teichmuller` (README 5.5, the Dependencies of Layer 5, the supplier contracts, and the description) is the file path turned into a namespace. The declaration is `TauCeti.teichmuller` in `TauCeti/RingTheory/Henselian/Teichmuller.lean` (line 94, inside `namespace TauCeti`).

## C08 — The `letI` in five signatures hides which structure the statement is about

`exists_residueSentence`, `exists_valueGroupSentence`, the two AKE theorems and the `ℚ_p` theorem introduce `valStructure K V` by `letI` inside the statement, so the elaborated type prints `K ⊨ ψ` and `K ≅[valLang] K'` with no visible dependence on `V`, and a later user rewrites under `let` binders. An explicit `@Language.ElementarilyEquivalent valLang K K' (valStructure K V) (valStructure K' V')`, or a type synonym carrying `V`, would state the same thing in the open.
