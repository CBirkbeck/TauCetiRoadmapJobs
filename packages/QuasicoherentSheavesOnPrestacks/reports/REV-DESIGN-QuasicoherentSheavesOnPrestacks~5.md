1. **F01** (P2) 2.3 states pointwise detection in a form that includes a false clause, and its Check misdescribes the instance

   Location: `packages/QuasicoherentSheavesOnPrestacks/design/README.md` line 322, "a map, or an object, is an equivalence, or zero, exactly when every evaluation is"; and line 329, "Joint conservativity uses all points: on `BΓ × Spec 𝔽₂` with `Γ = ℤ/2`, the nonzero class of 2.2 is a map `O → O[1]` whose evaluation at the atlas point is zero." `plan.json` 2.3, test `one_point_insufficient`, says the same.

   Claim: as written the sentence reads either as "a map is an equivalence, and an object is zero, exactly when every evaluation is" (the reading of `plan.json` 2.3, API `conservative`: "A map is an equivalence iff all evaluations are", statement "equivalences and zero objects are detected pointwise") or as "a map (or an object) is an equivalence (or zero) exactly when every evaluation is", which includes "a map is zero exactly when every evaluation is zero". The second clause is false, and the Check's own instance refutes it.

   Witness: on `X = BΓ × Spec k`, `Γ = ℤ/2`, `k = 𝔽₂`, `QCoh(X) = Fun(BΓ, Mod_k)` and `π₀ Map(O, O[1]) = H¹(ℤ/2; 𝔽₂) = 𝔽₂`. A point `(A, η)` of X has `η ∈ BΓ × Map(k, A)`; BΓ is connected, so every point is homotopic to the composite `Spec A → Spec k → X` through the atlas point, and every evaluation `η^*` is the forgetful functor `Fun(BΓ, Mod_k) → Mod_k` followed by `A ⊗_k −`. The forgetful functor carries the nonzero class to a point of `Map_{Mod_k}(k, k[1])`, whose `π₀ = Ext¹_k(k, k) = 0`. So every evaluation of the nonzero map `O → O[1]` is the zero map: vanishing of maps is not detected pointwise, because `π₀` of the limit of mapping spaces `Map(F, G) = lim_η Map(F(η), G(η))` (2.2) is not the limit of the `π₀`. The Check's heading "Joint conservativity uses all points" is false for this X: the atlas point alone is conservative for equivalences and zero objects on X, since every evaluation factors through it up to homotopy and `Fun(BΓ, Mod_k) → Mod_k` is conservative; and the Check's wording suggests that some other point detects the class, which none does.

   Repair: in 2.3 write "a map is an equivalence, and an object is zero, exactly when every evaluation is; the vanishing of a map is not detected pointwise". Replace the Check by: "Vanishing of maps is not pointwise: on `BΓ × Spec 𝔽₂` with `Γ = ℤ/2`, every point factors up to homotopy through the atlas point `Spec 𝔽₂ → X`, so every evaluation of the nonzero class `O → O[1]` of 2.2 is the zero map `A → A[1]`, `Ext¹_A(A, A)` being 0, although the class is nonzero; `π₀` of a limit of mapping spaces is not the limit of the `π₀`. Equivalences are detected pointwise all the same (1.5)." In `plan.json` 2.3 rename the test to `vanishing_not_pointwise` with that statement; the API `conservative` and the `statement` field already carry the intended reading and need no change. Tested on the refuting instance: with the clause removed, the remaining statement holds on X, where `O → O[1]` is not an equivalence and its evaluations `A → A[1]` are not equivalences either, and `F = 0` exactly when its underlying k-module is 0.
