**Where the repair departs from the review's wording, and why.**

- **The review's Check said "an fppf sheaf need not satisfy descent along it" (`ℤ → ℤ[1/p] × ℤ_p`).** That sentence is replaced. As written it asserts that some fppf sheaf fails descent along this particular cover, and neither the review nor the design gives such a sheaf. The Check now states only what is computed:
  - Φ′ is strictly smaller than Φ, because a quotient of a finitely generated ℤ-algebra is countable and `ℤ_p` is not.
  - A definition without finite presentation would make the fppf sheaves equal to the fpqc sheaves. That is the wrong model the Check excludes.
- **The review's sentence "on affine schemes the topology is Mathlib's `fppfTopology`".** It compared covering families, but `fppfTopology` is `fppfPrecoverage.toGrothendieck`. To compare sieves you also need that its covering sieves are exactly those containing a covering family. That is `Precoverage.mem_toGrothendieck_iff_of_isStableUnderComposition` (PrecoverageToGrothendieck.lean:166). It applies because:
  - `fppfPrecoverage` derives stability under composition and base change (Fpqc.lean:43);
  - it contains the isomorphisms (Sites/MorphismProperty.lean:104);
  - schemes have pullbacks (Precoverage.lean:186).

  The lemma is added to the contract and to 2.5's *Needs*.
- **The review asked for "1.1" on 2.5's *Needs*.** It is not added. 2.5 only uses products and faithful flatness of ordinary rings, which are Mathlib's: the flatness convention says so for discrete rings. Adding 1.1 would be a dependency the statement does not have.
- **The definition's position.** It is a prose paragraph in 2.5, after the definition of `X^♮` and before the API list, instead of an item inside the API list. 2.5 restates the (d)–(e) argument instead of citing 3.1's, so that 2.5 needs nothing later.

**Pattern repaired elsewhere.** The pattern is an fppf-local fact used to conclude something about the fpqc sheafification or `QCoh`. Searching for "fppf", "stack of", "torsor" and "sheafification" found one more instance: 3.3's Check on a finite group Γ. It said that `BΓ × Spec k` and the stack of Γ-torsors "have the same sheafification" and gave no link.

- The Check now says that the map between them is inverted by `L_fppf`. The torsor stack is `L_fppf` of the trivial-torsor prestack (2.5), whose automorphisms `Γ(R)` are constant on the members of a finite Zariski cover. So L inverts the map (3.1).
- 3.3's *Needs* gains "2.5 (`L_fppf`, for a Check)", following the README's convention of listing what Checks use. The plan's 3.3 follows.
