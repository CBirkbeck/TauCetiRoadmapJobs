## R01 (P2) — Reconcile Layer 1 ownership with the actual pinned library

**Location:** `packages/AmenableTracesOnCStarAlgebras/design/README.md:190`, “No Tau Ceti module is consumed”; also lines 147, 309–335 and 430–455, and `packages/AmenableTracesOnCStarAlgebras/design/plan.json:6`.

**Claim:** The inventory describes older pins and makes the roadmap own results now proved in the pinned Tau Ceti: convexity, relative weak-star closure and unital compactness of tracial states, and cyclicity, functional recovery and separation for tracial GNS representations. The assertion that the C*-algebra folder contains only character-space measures and unitary characters is false at the supplied pin. The Frobenius inner product is no longer real-only either.

**Witness:** `TauCeti/Analysis/CStarAlgebra/Action/KMS/Basic.lean:237` identifies 0-KMS states with norm-one tracial positive functionals; `TauCeti/Analysis/CStarAlgebra/Action/KMS/StateSpace.lean:119` proves their convexity, and line 148 proves unital compactness.

The actual revisions in `lake-manifest.json:10` and line 22 are Tau Ceti `2fd255d997f47c0b5d834ee416c7015d55444ce5` and Mathlib `1b1ccf4b088b32fa3f23f2de1127433254a81e1e`. The design instead records `358314d4ab97483df4fc4cb8adcc02e74a8d9f5a` and `f6090c7095e1e56b3464c1daba5f24631f1290d2`. The additional native declarations, with their hypotheses, are recorded below.

**Exact repair:** Refresh both inventories against the supplied manifest. In scope and supplier contracts, identify tracial states with the native 0-KMS predicate, for example for the trivial action, and cite the native convexity, closure, compactness, cyclic-vector, recovery and separating-vector results. Remove their duplicate proof targets from README and plan; retain the identification and genuinely additional tracial constructions. In particular, the normal tracial extension, right representation and tensor functional still need their stated interfaces. Cite the complex Frobenius API and algebraic trace-radical API where used; do not claim that either already supplies the whole normalized `CStarMatrix` interface or the closed nonunital trace kernel.

**Repair test:** For `A = M₂`, `tr₂` is 0-KMS, whereas `x ↦ x₁₁` fails the trace identity with values 1 and 0. The native convex set for `ℂ²` is exactly `{(t,1−t) : 0 ≤ t ≤ 1}`. For `c₀`, `δ_n → 0` weak-star but the limit has norm 0, so use the native relative-closure theorem, not unconditional closure. On the GNS space of `(M₂,tr₂)`, `Ω = I`, `L_x Ω = x`, and `⟨e₁₂,e₁₂⟩ = 1/2`; the native cyclicity and separation statements give precisely the claimed results.

## R02 (P2) — Preserve the nonzero qualification in the injectivity contract

**Location:** `packages/AmenableTracesOnCStarAlgebras/design/README.md:249`, “equivalent to a norm-one projection B(H) → M”.

**Claim:** The V13a contract drops the supplier's nonzero qualification. The conventions explicitly admit the zero algebra; this contract is stated for general von Neumann algebras, without a tracial-state hypothesis forcing nonzeroness.

**Witness:** `TauCetiRoadmap/VonNeumannAlgebras/README.md:4658` specifies a contractive projection, of norm one when `M ≠ 0`. For `H = 0`, `M = B(H) = 0`, the only projection has norm 0.

**Exact repair:** Say “equivalent to a contractive projection B(H) → M, of norm one when M ≠ 0.” Preserve the supplier's concrete faithful-normal-representation context. Add the zero-algebra control to the contract discussion or relevant Checks. No change to the trace-bearing applications is necessary: a norm-one state already excludes zero.

**Repair test:** On `B(0)`, the zero map fixes every element, has the required range and satisfies `‖P‖ = 0 ≤ 1`; it cannot satisfy `‖P‖ = 1`. For `M = B(ℂ)`, the identity projection has norm 1. Both cases now agree with V13a and its `IsInjective` definition.

## R03 (P2) — Order ideal extension after the tracial GNS input it uses

**Location:** `packages/AmenableTracesOnCStarAlgebras/design/README.md:402`, “with traciality from the normal vector trace of the weak closure of π_τ(I)”; compare lines 430–442 and the corresponding plan prerequisites.

**Claim:** The route for ideal extension in §1.3 uses the faithful normal tracial vector functional on the GNS weak closure. That is a result of §1.4. Its nonunital case explicitly transports through §1.3. The declared §1.3 inputs V0, V1 and V4 give ordinary GNS data and normal vector states, not this tracial-extension result. The current section-level route therefore has a hidden backward edge.

**Witness:** For `I = c₀ ⊂ c`, the ideal-extension route requires the nonunital tracial GNS result: §1.3 → §1.4. README line 442 explicitly sends the nonunital case of §1.4 through §1.3, closing the loop.

**Exact repair:** Separate the elementary unitization theorem from ideal extension. Establish unitization first, then the tracial GNS result with nonunital transport using only unitization, then ideal extension using that GNS result. Move the ideal-extension paragraph, its API and Check to that later position; update the plan prerequisites and all references. Merely adding §1.4 to the present §1.3 Needs line would retain the loop. An independent elementary proof of ideal-extension traciality would also resolve it, but its inputs must be stated instead of invoking the later vector trace.

**Repair test:** For `τ = Σ_{n≥1}2⁻ⁿδ_n` on `c₀`, unitization gives `τ̃(x) = Σ2⁻ⁿx_n` on `c` before the GNS theorem is invoked. The later ideal-extension theorem recovers that same formula. For `I = M₂ ⊕ 0 ⊂ M₂ ⊕ ℂ`, it gives `γ(x,λ) = tr₂(x)`. The resulting order is unitization → tracial GNS → ideal extension, with no return edge. This finding concerns the stated proof route, not the truth of ideal extension.

## R04 (P3) — A zero block multiplicity loses injectivity, not unitality

**Location:** `packages/AmenableTracesOnCStarAlgebras/design/README.md:540`, “multiplicity 0 for the second block would make ρ non-unital and non-injective”.

**Claim:** The zero-weight Check incorrectly attributes loss of unitality to dropping a summand in the multiplicity representation.

**Witness:** With multiplicities `(N,0)` and target `M_N`, `ρ(a,b)=aI_N`. Thus `ρ(1,1)=I_N`, `ker ρ=0⊕ℂ`, and `tr_N∘ρ=pr₁` exactly. At `N=1`, this is the unital coordinate projection.

**Exact repair:** Replace the quoted clause by “multiplicity 0 for the second block gives a unital but non-injective map; positive multiplicities are needed for an embedding.” Keep the `(N,1)` approximation and its error unchanged.

**Repair test:** At `N=1`, `ρ(1,1)=1` and `ρ(0,1)=0`. For positive multiplicities `(N,1)`, the map is faithful and the dual-norm error remains `2/(N+1)`. The corrected Check separates unitality from faithfulness.
