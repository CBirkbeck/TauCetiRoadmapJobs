## C01 — The comparison that §2.5 asks to prove, between the relative `Proj` over an affine base and Mathlib's `Proj`, is already the pinned chart square

An implementer would plan work the library has already done. §2.5 (line 489) asks to prove "that over an affine `S` it is Mathlib's `Proj` of the graded ring `A(S)`". Scope and ownership (line 1763) lists "the affine comparison with `Proj`" among the API "that the library lacks". Tau Ceti's `CategoryTheory.CommMon.isPullback_relativeProjCover` (`RelativeProj/Basic.lean:266`) makes the chart `Proj (⨁ n, Γ(Aₙ, U)) → relativeProj A` the base change along `U ↪ S` for every affine open `U`. Take `U = S`: the inclusion is an isomorphism, so the chart is an isomorphism over `S`. SchemeAndStackFoundations §0.3 on main derives its `relativeProj_affine_iso` the same way.

The fix: in §2.5, cite `isPullback_relativeProjCover` at `U = S` for this clause instead of listing it as a target, and drop "the affine comparison with `Proj`" from the sentence at line 1763. Base change and Veronese invariance remain targets: neither is at the pin.

## C02 — The new twisted-cubic Check in §2.2 calls `Y` a nodal cubic, but in characteristic 2 it is cuspidal

At line 428, `Y` is `y² = x²(x + 1)`. In characteristic 2, `y² + x² = (y + x)²`, so the equation becomes `(y + x)² = x³`, a cusp. The values the Check needs do not change: `h⁰(𝒪_{X₀}) = 2`, `h¹(𝒪_{X₀}) = 1`, `χ = 1`. The first Check of §2.2 (line 421) uses the same cubic and a short Weierstrass family, so it also assumes characteristic not 2. Adding "over a field of characteristic not 2" to the two Checks, or writing "plane cubic" at line 428, makes them true as written.
