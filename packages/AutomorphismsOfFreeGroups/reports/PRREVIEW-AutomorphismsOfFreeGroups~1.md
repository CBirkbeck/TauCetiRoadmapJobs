# Review of AutomorphismsOfFreeGroups (pull request #3179 at fe0694b)

**Verdict:** needs changes

**Summary.** Changes are needed, for two reasons that are not about the truth of any statement: Nielsen's generation theorem for `Aut(F_n)` (§1.4) is also planned and owned by MappingClassGroupsAndCanonicalRepresentations §9.6, an open roadmap earlier in the merge order that this README never mentions, and two definitions of `Suggested.lean` (`invAt`, `autToGL`) carry `sorry` in their bodies. Every statement, Check and convention I recomputed is correct, and all cited library declarations exist at the pins with the stated meaning. There are one small correction and two format notes, none blocking; the Lyndon–Schupp and Nielsen locators could not be read and are left to the human reviewers.

## R01 (P2) — Nielsen's generation theorem has two owners: §1.4 here and §9.6 of MappingClassGroupsAndCanonicalRepresentations

Two roadmaps that each plan a proof of the same theorem will produce it twice, with two generating sets and two sets of names, and neither README tells an implementer which one to build on.

MappingClassGroupsAndCanonicalRepresentations (pull request #2266, a new roadmap, placed before this one in the merge order) has in `TauCetiRoadmap/MappingClassGroupsAndCanonicalRepresentations/README.md`, §9.6, lines 2340–2348, the target "Prove that for `N ≥ 1` … `Aut(F_N)` is generated by the cyclic shift …, the transposition of `x₁` and `x₂` …, the inversion `x₁ ↦ x₁⁻¹` and the transvection `x₁ ↦ x₁x₂`", with route "Nielsen reduction of a basis" and the same supplier `TauCeti.FreeGroup.nielsenMul`; its scope section lists "Nielsen generation of `Aut(F_N)`" among what it owns (lines 2926–2927). Here §1.4 proves `nielsenSubgroup ι = ⊤` and *Scope and ownership* claims "Nielsen's generation theorem (Layer 1, S1)". The two generating sets differ (four generators there; all permutations, all inversions, all right multiplications here), but each is conjugate into the other by permutations, so it is one theorem. Neither README names the other roadmap.

The smallest change is one owner and one citation. Either (a) this roadmap cites MappingClassGroupsAndCanonicalRepresentations §9.6 for the generation statement, and §1.4 becomes the deduction of `nielsenSubgroup ι = ⊤` from it (keeping §1.3, which that roadmap uses as a route but does not state as targets); or (b) this roadmap, which is the natural home of the theorem and of Nielsen reduction, is the owner, placed before that roadmap in the merge order (its only roadmap supplier, TeichmullerGeometry, is earlier still), and that roadmap's §9.6 is changed to cite §1.4 here. Option (b) needs agreement with the author of #2266; in either case add the other roadmap to the neighbours paragraph and to *Scope and ownership*, and say in the description which was chosen.

## R02 (P2) — `invAt` and `autToGL` are definitions with `sorry` in their bodies

The acceptance file may use `sorry` only as the proof of a stated theorem. Here the fact that `B` is multiplicative, which §2.2 lists as a target ("from which multiplicativity follows"), is asserted by `map_mul' := sorry` inside the definition of `autToGL` (line 66, with `map_one'` at line 65), and `invAt` (lines 31–32) has `left_inv := sorry` and `right_inv := sorry`. Every later declaration (`nielsenSubgroup`, `IA`, all four theorems of Layer 2) is then built on a definition that depends on an unproved obligation.

The data fields are honest and the obligations are true, so the repair is to prove them; both proofs are short and I elaborated them at the pins. For `invAt`, `left_inv` and `right_inv` are the same six lines (after unfolding, `rw [← MonoidHom.comp_apply]`, then `FreeGroup.ext_hom` and `by_cases h : k = i <;> simp [h]`); alternatively build it with `MonoidHom.toMulEquiv` as `TauCeti.FreeGroup.generatorInversion` does. For `autToGL`, prove the transformation formula for `autMatrix` first and use it:

```lean
theorem expSum_autMatrix (γ : MulAut (FreeGroup ι)) (w : FreeGroup ι) :
    Multiplicative.toAdd (expSum (γ w)) = autMatrix γ *ᵥ Multiplicative.toAdd (expSum w) := by
  induction w using FreeGroup.induction_on with
  | one => simp
  | of j => ext i; simp [autMatrix, expSum, Matrix.mulVec, dotProduct, Pi.single_apply]
  | inv_of j ih => simp only [map_inv, toAdd_inv, ih, Matrix.mulVec_neg]
  | mul x y hx hy => simp only [map_mul, toAdd_mul, hx, hy, Matrix.mulVec_add]

noncomputable def autToGL : MulAut (FreeGroup ι) →* GL ι ℤ :=
  MonoidHom.toHomUnits
    { toFun := autMatrix
      map_one' := by ext i j; simp [autMatrix, expSum, Matrix.one_apply, Pi.single_apply]
      map_mul' := fun γ δ => by
        ext i j
        have := congrFun (expSum_autMatrix γ (δ (FreeGroup.of j))) i
        simpa [autMatrix, Matrix.mul_apply, Matrix.mulVec, dotProduct] using this }
```

This elaborates with no warning. The headline `expSum_apply` is then this lemma read through `autToGL`, so it would be proved rather than left with `sorry`, or dropped from the file in favour of the README target.

## C01 — No statement of Layer 2 has a source locator

A reader who wants to check the surjectivity of `B`, the containment of the inner automorphisms in `IA`, or the descent to `Out(F_n) → GL_n(ℤ)` against the literature has nowhere to look: §§2.1–2.4 cite only libraries and TeichmullerGeometry, and all six locators of the README are in Layer 1 and in *Downstream consumers*. The statements are standard and I verified each by computation, so nothing is unsupported mathematically; a locator at each of §2.3 and §2.4 would complete them (the discussion of the map `Aut(F) → GL(n, ℤ)` and its kernel in the chapter of Lyndon–Schupp already cited, or Magnus–Karrass–Solitar §3.5, would serve; I could not open either to give the number).

## N01 — The module docstring does not say which headline is not stated

The summary's last headline, that `B` descends to `Out(F_n) → GL_n(ℤ)`, is absent from `Suggested.lean`, correctly, since the outer automorphism group of a group is TeichmullerGeometry §4.2's and is not in the pinned libraries (Tau Ceti has only `TauCeti.OuterAlgAut`, for algebras). The docstring's "Stated here" paragraph would say so in one sentence, and likewise that the `FreeGroupBasis` form of `B` is left to the README.

## N02 — Four names in code font are declared nowhere, and one declared name is not in the README

`FreeGroupBasis.mulAutEquiv` (§1.1), `mulLeft` (§1.2), `IsNielsenReduced` (§1.3) and `FreeGroupBasis.autToGL` (§2.2) are proposed names, not declarations of `Suggested.lean`, so a reader cannot tell them from existing ones; say they are proposed, or write them in prose. Conversely `autMatrix` is declared in the Lean file and never named in §2.2. The labels "(S1)" and "(S2)" in the layer headings are not explained anywhere.
